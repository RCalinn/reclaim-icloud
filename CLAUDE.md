# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Personal-use Firefox extension (Manifest V2, Firefox ≥ 115) that finds similar photos in an iCloud Photos library, suggests which to keep, and moves the rest to Recently Deleted. It uses iCloud's undocumented CloudKit web API. There is no build step: the files are loaded as-is.

## Commands

- Load / reload the extension: `about:debugging#/runtime/this-firefox` → "Load Temporary Add-on…" (pick `manifest.json`) or **Reload**. The toolbar button opens `review.html`; an `icloud.com/photos` tab must be open and logged in.
- Unit tests (Node ≥ 22, no install needed): `npm test`
- Single file / single test: `node --test tests/grouping.test.js` · `node --test --test-name-pattern="favorites" tests/*.test.js`
- End-to-end in headless Firefox (needs `npm install` once for selenium-webdriver; uses `/Applications/Firefox.app` or `$FIREFOX`, port 8765): `npm run e2e`
- Large-library check (~19k photos, expiring links, 429s; takes ~10 min, port 8766): `node tests/e2e/scale.mjs [bursts=5700] [ttlSeconds=60]` (`bursts` ≈ photos / 2.9)
- Scan-speed benchmark: `node tests/e2e/bench.mjs [latencyMs] [throttleShare] [bursts]`

Git: public repo `RCalinn/reclaim-icloud` (the extension is called Reclaim iCloud; its gecko id stays `icloud-similar-photos@local` so saved signatures and choices survive), version branches `v0.2`, … (follow the release workflow; `dist/` holds the built zip and is git-ignored). `tests/equivalence.test.js` runs the pre-refactor `review.js` from `../iCloud Ext (backup 2026-10-04 before refactor)/` and is skipped if that folder is missing. The `*.new-features.bak` files in the root are the old single-file version; nothing loads them, so don't edit them or mistake search hits in them for live code.

## Architecture

**Request path to iCloud.** The review page cannot call iCloud directly: the request would carry a `moz-extension://` origin. Instead, `js/icloud.js` → `browser.runtime.sendMessage({type:'ck'})` → `background.js`, which learns the CloudKit endpoint (base URL + `dsid` query) by watching icloud.com's own requests via `webRequest` → `content.js` in the icloud.com tab runs `content.fetch` with the page's cookies. "Reload the iCloud Photos tab" in the UI means the endpoint hasn't been seen yet. Thumbnail/preview downloads (`*.icloud-content.com`) are fetched directly from the review page.

**Similarity engine.** Each photo gets a DINOv2-small embedding (`js/embed.js`: 168×168 squashed input, CLS token, L2-normalised, stored as Int8×384), computed by onnxruntime-web on WASM in the analysis workers. The runtime is vendored in `vendor/ort/` (wasm bundle, single-threaded; each worker loads its own session) and the model is `models/dinov2-small-int8.onnx`; the manifest CSP adds `'wasm-unsafe-eval'` for it. Pair score (`signature.js` `distance`) = `embScore` = 110 × (1 − cosine) when both photos have an embedding, else the classic score (also for a mixed pair where only one photo has an embedding; that case isn't calibrated, and only arises after a model failure); both sit on one scale, lower = more similar, and the Similarity slider maps to threshold `T = 12 + slider` (default slider 2 = cosine 0.873, set from the user's own Check accuracy labels; level 10 = 0.80). The scale was calibrated on 812 INRIA Holidays photos (see the comment at `EMB_SCALE`); synthetic fixtures are meaningless to DINOv2, so don't tune it on them. If the model can't load (`analyze.js` `modelReady()` false) or a worker isn't available, photos get only the classic signature and are re-analysed on a later scan that has the model.

**Pure vs. page code.** `js/signature.js` (pHash + 4×4 Lab colour on 64×64 RGBA; sharpness + exposure on 224×224 via `quality`), `js/embed.js` (all but `createEmbedder` is pure maths) and `js/grouping.js` have no DOM or app-state access, so they run in Node tests and in the worker. Classic score (`classicDistance`) = pHash Hamming distance + 0.3 × colour difference. The colour difference (`colourDiff`) is mean |ΔLab| per cell, or less when the pair only differs by a whole-picture exposure/saturation/white-balance change (fit and charge the leftover); it never goes below the pHash distance. `distance(a, b, limit)` may stop early above `limit` (classic only), and the equivalence test runs `group(…, score)` with the old formula. Everything else in `js/` is page code; `js/app.js` is the entry (`<script type="module">`). `ui.js` and `viewer.js` import each other; keep their top-level code free of each other's imports (shared helpers live in `dom.js`).

**Scan flow** (`app.js` `scan()`): `listLibrary` pages through `CPLAssetAndMasterByAssetDateWithoutHiddenOrDeleted` (videos are counted, not analysed; a page iCloud fails with 5xx/429 is retried, then re-read in smaller pages so only an asset it always fails on is skipped, and then pruning is skipped too) → `store.pruneTo` drops saved data for vanished photos (skipped if the listing is empty or under half the cache; that guards against iCloud hiccups) → `applyCache` (a photo saved without an embedding counts as uncached when the model runs) → `modelReady()` loads the model in every worker, only if something needs analysing → uncached photos are downloaded by `adaptivePool` (8→24 parallel, cut 30% on 429) and analysed in `analysis-worker.js` (module worker + `OffscreenCanvas`; `analyze.js` falls back to the main thread, classic signature only, if workers fail or a job hangs 60 s) → `regroup()`. The model makes analysis the bottleneck (~0.2–0.35 s per photo per worker).

**Grouping** (`grouping.js` `group(items, T, W)`): a candidate graph (pairs ≤ 1 h apart, plus near-duplicates at any gap: pHash within 6 bits, found by LSH, and score ≤ 6) is built once per library and cached by `items` identity. Each slider change walks edges with time-relaxed thresholds and capped complete linkage → **sets** of near-identical shots (keeper first via `rank`: favorite > resolution > exposure (clipped share, 10% steps) > sharpness at 224 px > size). More than 20 photos sharing one exact timestamp (bulk imports) are treated as undated, so they only match as near-duplicates. Sets are then joined into **moments** (one card each). Sets spanning more than max(time window, 1 h) can only come from near-duplicate copies saved much later. They are excluded from time-based joining, because otherwise they swallow everything in between into one giant card. Display order is oldest first, in month blocks (`ui.js`).

**State and persistence** (`store.js`, `browser.storage.local`): `signatures-v3` is the signature cache, keyed by asset id: `[pHashHi, pHashLo, sharp, lab, expo, emb | null]` (bump `CACHE_KEY` in `config.js` and list the old key in `OLD_CACHE_KEYS` if the signature format, the model or `EMB_SIZE` changes). `choices-v1` holds the user's Keep/Delete overrides plus `emptyOK` (sets deliberately left with nothing kept). Saves are debounced 300 ms and flushed on `pagehide`. `isDeleted(p)` = override if present, else `suggestDelete` (not the set's keeper and not a favorite). `sanitizeChoices` never lets a set end up with nothing kept unless the user did that explicitly.

**Built for ~20k-photo libraries.** iCloud download links are signed and expire. `renewLinks` re-fetches a photo's links whenever they fail as expired, at most every 20 s per photo; a long review outlives several renewals. `images.js` keeps downloaded images in a bounded LRU of object URLs (revoked on eviction) and skips queued requests whose tile scrolled away. `ui.js` builds cards in chunks of 40 as you scroll, and tiles release their image once far off-screen. Avoid reintroducing anything that renders or downloads all groups at once.

**Check accuracy** (`tune.js` sheet; pure maths in `accuracy.js`): the user labels pairs of photos taken ≤ 1 h apart (sampled evenly across scores 6–44) as same shot / different, stored in `labels-v1` keyed by sorted asset-id pair. Results score every Similarity level with `distance` + `threshold` (pairwise, an approximation of the real grouping), suggest one (a wrong group costs 3× a miss) and can move the slider; slider positions persist in `settings-v1`. "Download labels" (format version 2) exports classic signatures, each pair's embedding cosine (never the vectors), time gaps, answers and the names of fields seen on iCloud records (`icloud.js` `seenFields`), never ids, names, dates or links; that file is how `EMB_SCALE` gets tuned on the user's own photos. **Bursts:** photos sharing `burstId` (best-guess field name, unverified on a real library) start as one set in `group()` regardless of score.

**Deleting** sets `isDeleted: 1` on `CPLAsset` records via `records/modify` (50 per call, non-atomic, guarded by `recordChangeTag`). iCloud moves them to Recently Deleted. A delete can cover everything marked or one month (the block header button).

## Test harness

`tests/fixtures.js` draws deterministic synthetic scenes, so retakes and unrelated photos have known relationships under the classic score (Node grouping tests use only that). `tests/embed.test.js` runs the real model in Node from `vendor/` (no install) on `tests/photos/holidays-168.json.gz`: four real scenes, two shots each, already at 168×168. INRIA owns those photos, so the file is git-ignored (kept locally only) and the test is skipped without it. `tests/e2e/server.mjs` serves the extension plus a harness page: `review.html` with `tests/e2e/mock.js` injected, which fakes `browser.*` and CloudKit (paging counts videos, expiring `exp=` links, `records/modify`), backed by `localStorage`. Thumbnails are 64×64 PNGs of the fixtures, so worker pHash/colour must equal Node's exactly (sharpness and embeddings come from upscaled copies, so only their presence is checked). The workers run the real model, so a full scan of the 179-photo mock takes ~45 s; `run.mjs` `fresh(patch, keepSigs = true)` keeps saved signatures across page resets, and `/__h/model?block=1` makes the server 404 the model to test the classic fallback. WebDriver can't run scripts in a real `moz-extension://` page; to smoke-test the packaged extension (CSP, WASM), add a module to a copy of `review.html` that reports to a local server. `mock.js` also counts workers, in-flight downloads and object URLs, and collects page errors. To inject a fault, `run.mjs` `fresh(patch)` puts a JS string in `sessionStorage.patch`, and `mock.js` evals it before the app boots (for example, to make workers fail and test the main-thread fallback). Read UI text in Selenium via `textContent`: `getText()` returns "" while elements fade in.
